## 0. 一句话定位与三条红线

**定位**：从"POC 演示品"升级为"财智分公司共享审核的生产系统"。内核（SDAFI 规则引擎、三元本体、S→D→A→F→I 审计链）原样保留——这是我们的技术亮点；外壳（角色、动线、易用性、并发协作、留痕、容错）全部按企业级标准重做。

**红线（任何改动不得触碰）**：
1. **引擎层一行不动**：规则编译/执行、本体存储与装载、审计链、脱敏中间件。本期所有后端工作只允许"薄 API"（分配、意见、改判、日志、排序分页），不进引擎内部。
2. **数字不说谎**：一切 KPI/统计取自真实接口实测，不写死。
3. **每一步留痕**：企业级的判据是任何业务动作都能回答"谁、何时、对什么、做了什么、依据是什么"。做不到留痕的功能不做。

## 1. 什么叫"企业级"——本项目采用的判据清单

客户说"更像企业级产品"，翻译成可验收的判据（后续每个模块按此自查）：

| # | 判据 | 白话 |
|---|---|---|
| E1 | 多人协作不冲突 | 两个人抢同一单，系统只让一个成功，另一个有明确反馈 |
| E2 | 状态可见 | 任何单据/任务在任何时刻都能回答"现在在哪、归谁、卡了多久" |
| E3 | 动作可回溯 | 谁改了什么、为什么改，事后查得到，改不掉 |

## 2. 角色重新定义（4 角色，全部重排）

> 用户 2026-10-26 定调：**"系统工程师"（即原知识工程师）的界面里不该出现业务本体、流程本体；这个角色真实的工作是上传规则→审核→入库→存档；本体换个形态在别处展示。** 本节照此重排。

### 2.1 审核员（auditor，林嘉/陈芳——财智分公司审核岗）

**真实工作**：每天登录 → 看我的待办 → 认领 → 逐单复核（看 AI 结论、查附件、查规则依据）→ 提交（通过/退回）→ 对不认可的规则标异议。

| 菜单（重排后） | 内容 |
|---|---|
| **我的工作台**（登录落地页） | 待我复核 N、认领池（按单位过滤）、我的已审历史、我的统计（今日审单量/平均用时）——已实现（迁移 0043，10-26） |
| 单据审核（组） | 审核工作台（全量队列）→ 审核报告（复核闸门）→ 单据详情（附件三问） |
| 智能审核 | 触发一轮 AI 审核、进度、通过率/时效 KPI |
| 审计追溯 | S→D→A→F→I 全链查询 |

**体验目标（E7）**：登录第一屏 = 待办数字 + "开始审核"一个主按钮；键盘 ←/→ 翻单、回车提交，全程不碰鼠标也能干活。

### 2.2 规则管理员（engineer，原"知识工程师"，角色显示名待拍板）

**真实工作四步**（吸收《规则管理员角色重构方案》结论）：**传文件 → AI 跑一遍 → 逐条审定 → 打版发布**。

| 菜单（四项对应四步） | 内容 | 吸收的原功能 |
|---|---|---|
| **制度文件** | 上传**即自动进入抽取**（客户待办 #8"上传后直接同步抽取"）；文件清单、解析状态、来源切片查看（#4） | 制度文件库＋规则抽取合并 |
| **规则审定** | AI 草稿逐条采纳/驳回（审定人=登录人，禁手填）；**异议收件箱**：审核员回流的"不认可+修改意见"在此汇总处理（#2 回流侧） | 抽取审定页＋新增异议处理 |
| **规则库** | 生效规则全集（82 条→随抽取增长）；来源文件/条款号/原文切片一键展开（#4）；**页签「报销标准」**＝业务本体的业务价值部分换形态呈现（城市/职级/交通/住宿限额字典） | 规则详情＋业务本体(部分) |
| **发布管理** | 版本冻结→审定→签字→生效→回滚，生效版本列表 | 发布管理 |
| （高级，默认折叠） | 解析明细、抽取统计、排障底账 | 单步调试等实施工具移系统管理员 |

**从前端拿掉**（功能不删，只是这个角色看不见）：业务本体/规则本体/流程本体三页、本体工场八步流、增量指纹/列映射等实现层词汇。
**本体的去处见 §2.5。**

**对话式生成规则（#6）**：挂在"规则审定"页内一个入口（"用对话描述要求，AI 起草规则"），产出仍进专家审定管道——对话只是新的草稿来源，不新增菜单。

### 2.3 系统管理员（admin）

| 菜单 | 内容 |
|---|---|
| 用户与角色 | 账号 CRUD、角色权限、**单位数据权限**（财智+10 二级单位的多租户隔离基础，sys_user_org 已有） |
| 模型配置 | 11 厂商、连通性测试、按用途默认 |
| 运行监控 | 智能体运行状态（原"智能体工作台"改名，语言降维） |
| 系统自检 | Fail Fast 启动报告 |
| **操作日志（新增）** | 全站动作流水：谁·何时·何页·做了什么（登录/认领/复核/改判/审定/发布/回滚）。企业级硬需求（E3），后端一个中间件＋一张表，薄 API 不碰引擎 |
| 知识结构（只读，高级） | 本体三元结构的技术视图（系统管理员才看得见的"内部结构"页，给实施/排障用，不给业务角色） |

### 2.4 领导/主管（leader，王总）

| 菜单 | 内容 |
|---|---|
| 总览看板 | 总量/通过率/待人工/时效 KPI＋结论分布＋规则漏斗（已有） |
| 偏差与回流 | 四象限、隔离区、一致性自检＋**异议回流趋势**（#2 数据出口） |
| 审核队列（只读） | 工作台只读视图 |

**总览看板本期补两张卡**：审核时效（单均停留、超 48h 单量——共享中心的核心 KPI）与人效（人均日审单量，数据源 manual_review 已有 reviewer）。对位客户在用系统的"质量稽核+人员绩效"。

### 2.5 本体"换形态"的去处（一句话方案）

> 本体不是被砍掉，是从"业务界面"退到两个新位置：**值钱的部分变成业务字典，技术部分变成管理员视图。**

| 本体内容 | 新形态 | 在哪 |
|---|---|---|
| 业务本体里的限额/标准（城市、职级、交通工具、住宿标准） | "报销标准"业务字典 | 规则库页签 |
| 业务本体的概念/枚举（业务大类、单据类型） | 下拉选项的数据来源（本来就主要这么用） | 各表单 |
| 规则本体、流程本体、三元关系 | "知识结构"只读技术视图 | 系统管理员 |
| 本体工场八步流水线 | 实施工具 | 系统管理员高级区（或仅本地保留） |

## 5. 企业级细节考虑清单（E1–E7 展开，含状态）

> 这是对用户"两个审核员抢同一单怎么办"这类细粒度问题的系统化回答。**已做**=本期之前完成；**待做**=纳入 §6 分期；**生产期**=M5 或上线后。

**A. 多人并发与协作**
- 抢单冲突：同单仅一个有效认领（DB 部分唯一索引，非前端假锁），他人提交 409 拒绝——**已做**
- 认领超时自动释放：认领 24h 未处理自动回池，防"占着不审"——待做（M2，一张定时任务表+释放留痕）
- 会话过期优雅处理：12h 会话到期，前端统一跳登录并带"登录已过期"提示，不出 401 白屏——待做（M2）
- 批量操作事务性：批量通过逐张反馈、失败不中断、末尾汇总报告——部分已有（批量通过），补失败汇总——待做（M4 顺带）

**B. 审核效率（对位客户在用中兴新云：推拉双轨/信用分级/时效）**
- 键盘动线：←/→ 翻单、提交自动下一张——已做
- 队列排序：风险（命中数）/金额/时间，服务端排序保证翻页稳定——前端已有，**服务端排序待做**（M4，后端缺口已登记：现前端全量拉取 50 页封顶 1 万张，40 万单/年必须服务端化，E5）
- AI 预审分流：AI 高把握通过的单不进人工池（manual=none 过滤已有），池子默认只剩该人看的——已做
- 时效 SLA：单据进入待审超 48h 标红、看板统计超时量——待做（M2 看板卡+列表标红）
- 工作量可见：认领池显示各审核员在办数（组长调备用）——待做（M4 顺带，数据已有）

**C. 规模与性能（E5）**
- /api/bills 服务端分页/排序/筛选——待做（M4，最重要的后端缺口）
- 附件原图懒加载+缩略图——部分已有，补列表页懒加载——待做（M4 顺带）
- 报表导出 xlsx（复核记录/异议清单）——生产期

**D. 留痕与审计（E3）**
- 全站操作日志（§2.3 新增页）——待做（M2，中间件+一张表）
- 人工改判/补录留痕（#3）——待做（M4）
- 异议意见留痕（#2）——待做（M4）
- 发布/回滚留痕——已有

**E. 空态/错态/权限态（E4）**
- 每页空态"一句话+一个动作"——已有规范，随 M2 逐页过
- 接口失败重试与错误提示（无静默失败）——传输层已收口，逐页过——M2
- 无权限页面统一 403 页（现 401/403 混用）——M2 顺带

**F. 安全**

### 8.1 换装过程抓到并修掉的三个外壳缺陷（2026-10-26 晚，教训入册）

1. **菜单整棵不渲染**：`<a-menu :items="[]"">` 传了空 items——AntD 4 里 items 属性优先于插槽，空数组直接吞掉插槽菜单。教训：用插槽就绝不传 items。
2. **侧栏随页面滚走**：初版侧栏没做 fixed，内容一长菜单滚出视口。AntD 标准做法是 fixed-sider + 主区 margin-left 让位，已按此修（实测滚到底部 siderTop=0）。
3. **三张表竖排"疯狂罗列"**：初版把待办/池/已办堆三张卡一屏拉三屏长。改成单卡 + a-tabs（待办任务|待认领|已办记录 带计数），一屏收齐。教训：**同一页面的多段列表默认用 Tabs 或分栏，不竖排堆叠**——此条列入 E7 设计守则。
