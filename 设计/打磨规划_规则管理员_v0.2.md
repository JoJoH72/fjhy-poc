### B-P0-2 附件识别结果人工可修改（客户 #3，11-12 节点）

- **背景**：客户排期表 #3 原文「新增人工修改与补录（改附件类型、改识别字段），修改留痕，避免 AI 识别错误影响审核」。现状附件自动分类（attach_type + 判定依据 + 把握度）与字段抽取（文字/日期）均只读；BillDetail 附件区已有「未判类型」批量补判（AI 补判，`classifyBatch`）——批量 AI 补判与人工单条改判是两件事，并存不合并。
- **标准依据**：薄 API 白名单明文——总体规划红线原文列了「分配、意见、**改判**、日志、排序分页」，改判是允许清单内的；五环（改判是动作，四态齐备地设计）；留痕三问（谁、何时、把什么从什么改成什么——前后值都要留）；「宁少勿糙」（改判不触发引擎重跑，scope 收死，见下）。
- **交互方案（控件级）**：
  - **改附件类型**（BillDetail 附件表行内）：attach_type 单元格 hover 出「订正」icon 按钮 → `a-select`（options=附件决策表 11 类，数据源 lookup 表不写死）就地选择 → 确认。订正后单元格显示 `人工订正` blue tag + hover tooltip（谁 / 何时 / 原判什么 / 依据 AI 原值可对照）。
  - **改识别字段**（抽屉）：字段区「订正」入口 → `a-drawer` width=560 列出该附件已抽字段（字段名 / AI 值 / 把握度 / 输入框）→ 逐字段改 → 提交。改过的字段行前 blue dot，AI 原值始终并列显示（「AI 原值：2025-12-14」灰字）——**人工值与 AI 值并列对照，不覆盖历史**。
  - **补录**（AI 未判类型的附件）：「未判类型」行加「人工定类」按钮（与批量 AI 补判并排、视觉区分：AI 批量=default，人工单条=primary ghost），走同款 a-select。
  - **权限**：auditor + admin（附件属审核域；engineer 不进 BillDetail）。前后端双闸。
  - **scope 红线（写进任务书防蔓延）**：改判只修数据与留痕，**不自动重跑审核、不触发引擎**——改完类型后是否重新判定是另一个动作（重跑审核已存在于既有链路），本条不做联动。
- **后端薄 API**：①`POST /api/attachments/{id}/reclassify`（body={attach_type}）；②`POST /api/attachments/{id}/fields`（body={updates:[{field, value}]}）。落库三件事：attachment 本表更新 + **改判台账表 `attachment_judge_log`**（INSERT-only：attachment_id / field / old_value / new_value / by / at）+ sys_op_log（detail 人话摘要，不含图片数据）。挂 `服务端/app/api/review.py` attachments 区段（L768 起）。
- **工时**：10h（薄 API 与台账 3 / BillDetail 行内+抽屉 5 / 权限与自测 2）。
- **优先级**：P0（客户项）。**文件冲突硬约束**：BillDetail.vue 已被 A线 6c2af9c 改过（对比块/大图/批量补判/重报 diff），A线 v0.2 的 A-P1-2（大图层复用）也要动它——三方叠加，**本条先做、A-P1-2 随后**，禁止并行；动手前 `git log --oneline -3 -- 前端/src/pages/BillDetail.vue` 确认基线。
