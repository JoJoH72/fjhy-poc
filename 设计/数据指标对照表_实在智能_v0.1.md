## 零、先读口径：这两组数字不在同一个量纲上

**不读这一节，下面每一行都会被误用。**

| | 实在智能（华电福建） | 本 POC |
|---|---|---|
| 运行阶段 | 生产稳定运行 | POC，单机本地 |
| 样本 | 真实生产单据，日均 3000 单量级 | 29 张**自造**演示单 + 40 张真实样本 |
| 准确率基准 | 测试平台按**人工标注**逐单比对 | 演示单真值**由我方自己写在生成器里**；40 张真实样本**无人工真值** |
| 规则 | 集团/区域/公司三级语义规则，全量上线 | 82 条规则资产，**仅 23 条进执行集**（剔除 59 条） |
| 算力 | 本地 GPU 集群，约 400GB 显存 | 无本地算力，调用阿里云百炼 API |

三条**不可直接比**的红线：

1. **准确率不可比。** 对方的 99% / 85% 来自真实单据 + 人工标注；我方的 100%
   来自自己造的 29 张单 + 自己写的真值——**自己出题自己判卷，分数不能和别人的考试成绩并列**。
2. **转人工率不可比。** 演示单里 22 张是故意带缺陷的，转人工率天然偏高；
   40 张真实样本的 22.5% 转人工也不是误驳，成因是取数缺口（见第二节）。
3. **吞吐可比性最高**（都是机器时延），但并发数、单笔计算量差异大，仍需同数据集压测才算定论。

## 一、吞吐与时延

| 指标 | 实在智能 | 本 POC（实测） | 读法 |
|---|---|---|---|
| 单笔端到端 | 约 4 分钟（现场口述，串行观测） | **规则链路 p50 388ms / p90 510ms**（29 单） | 规则链路快 3 个数量级，因为确定性判定不过模型 |
| 单笔端到端（含模型辅助） | 同上 | **11.4 秒/单均值**（330 秒 ÷ 29 单） | 我方只有 0.86 次/单模型调用，对方每条规则组都过模型 |
| 常规吞吐 | 约 5 单/分钟、200 单/小时 | **约 5.3 单/分钟、316 单/小时**（单进程串行，含模型辅助） | 数量级相当；我方未开并发 |
| 压测峰值 | 12 小时 3845 单（≈320 单/小时，10 并发） | **未做压测** | 这是缺口，不是优势 |
| 纯规则链路吞吐 | — | **29 单 / 11.9 秒 = 约 8,780 单/小时**（单进程，推算至小时） | 判得了的部分极快；判不了的才花钟点 |
| 并发上限 | 稳定 6，生产 10，再高错误率上升 | **未验证** | 我方瓶颈不在算力而在 API 配额，性质不同 |
| 阶段耗时 | 按 5/10/15 秒分档统计完成率 | S 135 / D 0 / A 153 / F 99 ms（p50） | 双方都有分环节度量；我方粒度到毫秒 |

**关键结构差异**：对方吞吐跃升靠「规则压缩 10 条→1 条，一次送模型」；
我方 23 条规则逐条确定性判定，**模型只在判不了的 25 条结论上介入**。
同样的 316 单/小时，对方烧的是 400GB 显存，我方烧的是 24,980 token。

## 二、准确率与人工成本

| 指标 | 实在智能 | 本 POC（实测） | 读法 |
|---|---|---|---|
| 自动通过样本可靠性 | 约 99%（人工标注基准） | **无人工真值，不出数** | 我方 600 条 pass 结论一条都没经人工确认 |
| 转人工样本中真实问题占比 | 约 15% | **不适用**（成因不同，见下） | — |
| 误驳率 | 约 85%（3000 单 ≈ 380 单无效转人工） | **演示集 0 误报**（但只声明了 4 条反向真值） | 我方分母太小，这个 0 说明力有限 |
| 查全率 | 口径未披露 | **100%（30/30 应命中全中）** | 真值自写，仅供回归用 |
| 单据级全对 | — | **29/29** | 同上 |
| 转人工率 | 拒单约 5% | 演示集 48%（14/29）、**真实样本 22.5%（9/40）** | 口径不同：我方 review 全部来自取数缺口 |
| 转人工成因 | 模型误判为主（85%） | **取数缺口为主**：出差地点/授权记录/出差起止日（G-01、G-04 等） | **这是本质差别**：对方是模型判错，我方是数据没到 |
| 真实样本命中数 | — | **0 命中 / 16 待人工 / 464 通过（40 单）** | 要么样本干净，要么规则覆盖不足——无真值无法区分，必须核 |

**这一节最该对外说的一句话**：我方现在**没有可对外引用的准确率**。
29 张演示单的 100% 是回归测试数字，不是准确率；40 张真实样本尚无人工标注。
对方的 99%/85% 是有基准的真数字（且报告已指出其两组口径 85%/15% 与 95%/5% 自相矛盾，须以测试平台明细为准）。

## 三、可解释性与数据溯源（我方设计上的差异点）

| 指标 | 实在智能 | 本 POC（实测） | 读法 |
|---|---|---|---|
| 结论追溯粒度 | 可追溯至**文档**，无法拆解至**数据项** | **可拆到数据项**：每条结论带 rule_id + 规则版本 + 证据字段 | 报告列为对方结构性短板 |
| 规则判定留痕 | 每条规则判定结果、驳回理由、原单可回看 | 同有，另加 **S→D→A→F→I 五阶段审计链**（5 张 hypertable） | 对方够用，我方更细 |
| 规则是否合并送模型 | 合并（10→1），牺牲单条可解释性换吞吐 | **不合并**，逐条确定性判定，判定可复现 | 同一张单重跑结论一致（幂等键钉住） |
| 模型介入是否标注 | 全链路过模型，无需区分 | **逐条标注** `llm_involved` + `llm_rationale`，模型结论不覆盖引擎结论 | 审核人能看出哪条是模型说的 |
| 脱敏 | 报告未涉及 | 6 条策略覆盖 9 个出口，响应带 `x-fjhy-masked` 头 | 送模型前先脱敏 |
| 模型调用留痕 | 报告未涉及 | 每次调用落 `llm_call_log`：成败、token、时延 | 本轮 25 次全成功，p50 12.0s / max 24.5s |

## 六、要把这张表变成可对外引用的东西，还差三件事

1. **同数据集压测**（报告自己也列为第一条建议）：同一批已标注单据、同一套规则，
   两边各跑一遍，比单笔耗时、通过率、误驳率、字段级准确率。否则第一、二节的
   并列只能当参考，不能当结论。
2. **40 张真实样本做人工标注**。现在 `manual_review` 表 0 行，意味着我方
   **一个准确率数字都不能对外说**。这是最便宜也最该先做的一件事。
3. **补齐执行集**：82 → 23 的落差里，59 条的剔除原因要逐条标清楚是
   「缺数据」还是「规则写不出」——前者可通过接口补，后者才是产品缺口。
