```bash
npm install
npm run dev   # http://localhost:5173
```

## 协作纪律（重要，三人约定）

1. **不要直接 push main**。本体/规则侧的改动一律开分支：
   ```bash
   git checkout -b onto-rules-xxx   # 分支名体现改的内容
   # ...改代码...
   git push origin onto-rules-xxx
   ```
   然后在 GitHub 上发 Pull Request 到 main，由 JoJoH72 侧 review 后合并。

2. **提交前必须跑测试，全绿才许 push**（这是双方的安全网）：
   ```bash
   cd 服务端
   python -m pytest tests -q
   # 预期：1072 passed, 39 skipped，0 failed
   ```
   测试覆盖了规则引擎/本体装载/审计链的全部行为契约——**本体侧的改动如果碰坏了引擎行为，这里会红**。

3. **边界约定**：
   - 何老师侧：本体（本体资产、规则口径、装载链的本体部分、`输入数据`里客户新文件的规则解析）
   - JoJoH72侧：前端页面、交互、产品功能、薄 API
   - 共享文件（如 `服务端/app/api/*.py`）：改前 `git pull` 拉最新，小步提交

4. **数据库迁移文件编号**：现在已用到 0052。何老师侧新增迁移请从 **0060** 起编号，避免冲突。

5. **客户数据不入库不入仓**：`输入数据/`、`材料/`、`服务端/var/` 都在 .gitignore 里，客户的单据/票据/制度文件不推 GitHub。
