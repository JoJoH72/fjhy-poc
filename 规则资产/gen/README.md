# 规则资产的生成与校验

两份文件是**生成物，不要手改**——手改必然与本体漂移：

| 生成物 | 生成器 | 输入 |
|---|---|---|
| `规则绑定_v0.1.json` | `gen/gen_bind.py` | `本体_v0.1.yaml` + `规则清单_v0.1.json` |
| `事实模型_v0.1.json` | `gen/gen_fact.py` | `本体_v0.1.yaml` + `规则绑定_v0.1.json` |

手改的文件（有注释，注释是最贵的部分）：

- `本体_v0.1.yaml`
- `规则清单_v0.1.json`
- `规则资产/标准表_v0.1.yaml`
- `规则资产/必要附件决策表_v0.1.yaml`
- `规则资产/敏感词表_v0.1.yaml`
- `规则资产/内部单位名单_v0.1.yaml`

**改这些文件一律走定点替换，不要 `yaml.load` 之后再 `dump`。** load→dump 会把全文注释
一次性抹光，而注释里记的是口径说明和踩坑记录，这种损失在 code review 里极难发现。

## 跑法（在项目根目录）

```
python -I 规则资产/gen/gen_bind.py      # 重新生成规则绑定
python -I 规则资产/gen/gen_fact.py      # 重新生成事实模型
python -I 规则资产/validate.py          # 校验（改完必须跑）
python -I 规则资产/validate.py --no-xlsx  # CI 里没有 材料/ 时
```

顺序有依赖：`gen_fact` 读 `规则绑定_v0.1.json`，所以先 `gen_bind` 再 `gen_fact`。

## 溯源脚本（一次性，留档备查）

- `gen/scan_att_source.py` —— 从 `财务共享业务场景核算及审核规则.xlsx` 的「业务域」表
  筛出 153 行差旅场景，按（业务大类编码 × 业务小类编码）去重成 29 行，
  并导出每行的「报账附件」原文变体。必要附件决策表就是照它的输出写的。
- `gen/scan_units_from_summary.py` —— 从 40 张样本的 40 条摘要里抽单位名与地名。
  内部单位名单的第三段（observed_with_place）出自这里。

这两个脚本的输出**不直接落成资产**，要人看过、判过可信度之后才手写进 YAML。
原因见 `规则资产/标准表_v0.1.yaml` 的三档可信度标注：
人眼读图可用于硬规则，OCR 不得直接进硬规则阈值，原生文本可用。
